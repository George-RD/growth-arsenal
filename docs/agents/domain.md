# Domain docs

Growth Arsenal uses a single domain context.

## Before non-trivial work

- Read `CONTEXT.md` at the repository root for canonical project vocabulary.
- Read ADRs under `docs/adr/` when they touch the area being changed.
- If either does not exist, proceed without ceremony. Create or update them through `/domain-modeling` only when a real term or durable decision needs recording.

## Rules

- Use glossary terms in specs, tickets, tests and code-facing documentation.
- Do not turn `CONTEXT.md` into a spec or implementation notebook; it is a glossary.
- Create ADRs sparingly: only for decisions that are hard to reverse, surprising without context, and the result of a real trade-off.
